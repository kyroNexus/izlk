# ИЗЛК CRM — контекст для Claude

## Проект

Внутренняя CRM ИЗЛК для договоров, проектирования, производства, площадок, документов и задач.

- Стек: Next.js 14 (App Router), TypeScript, Tailwind CSS v4, Prisma/PostgreSQL, NextAuth.
- UI: собственные компоненты и CSS-токены; внешние UI-библиотеки не добавлять.
- Основной язык интерфейса: русский.
- Текущая опубликованная база до рабочей серии изменений: `6440d4b` (`Release: reliability, workflows and design system`).
- Удалённый репозиторий: `https://github.com/kyroNexus/izlk`.

## Что менялось в текущей рабочей серии

- Чаты отделов и договоров: `ChatThread`, `ChatMessage`, страницы `/departments/[code]`, API `/api/chats`.
- График производства: `ProductionPlan`, `/production-schedule`, миграция `20260812151000_production_schedule`.
- Комментарии к этапам договора: `ContractStageComment`, API `/api/contracts/[id]/stage-comments`, компонент `StageCommentEditor`, миграция `20260812173500_contract_stage_comments`.
- Карточка договора: разделы переключаются вкладками через `ContractSectionNav`; одновременно виден один раздел.
- Добавлены миграции для чатов, производства и комментариев этапов. Их нельзя переписывать после применения.

## Важные UX-ограничения

1. Это не редизайн. Сохраняй существующую тёмную/светлую тему и визуальный язык.
2. Простота важнее декоративности: один primary-action на экран, вторичное сворачивать, не дублировать данные карточки договора.
3. Использовать существующие токены из `src/app/globals.css`, `src/components/ui.tsx`, `Icon.tsx`.
4. Не менять API, проверки прав, модели данных и бизнес-логику без отдельного обоснования.
5. Не добавлять зависимости и новые цвета/токены без явной необходимости.
6. Таблицы должны оставаться плотными, с единым форматом дат, чисел и hover-строки.
7. Проверять светлую и тёмную темы, мобильную ширину и `prefers-reduced-motion`.

## Задача для аудита

Сначала проведи аудит, ничего не меняй и не коммить. Верни ответ на русском в следующем формате:

| Экран / область | Конкретная проблема | Нарушенное правило | Минимальное исправление | Приоритет |
|---|---|---|---|---|

Обязательно проверь: dashboard, список и карточку договора, документы, задачи, площадки, проекты, график производства, рабочие зоны/чаты, контрагентов, исполнительную документацию, настройки, уведомления, inbox и login.

Затем предложи план маленьких независимых итераций: по одному экрану, с числом видимых контролов «было → станет». Отметь отдельно риски в текущей серии: доступы чатов, корректность Prisma-миграций, производственный график без утверждённых формул и доступность вкладок карточки договора.

Не пиши код до подтверждения пользователя.
