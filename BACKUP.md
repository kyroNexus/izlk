# Резервное копирование ИЗЛК

## Создать полный снимок

Из корня проекта:

```powershell
npm.cmd run backup:all
```

Команда создаёт отдельную папку в `backups\snapshots\<дата-время>`:

- `izlk-database_*.json.gz` — логическая копия PostgreSQL;
- `izlk-database_*.manifest.json` — модельный состав, число строк и SHA-256 БД;
- `izlk-files_*.zip` — файлы из `STORAGE_PATH`;
- `izlk-files_*.manifest.json` — число файлов и SHA-256 ZIP;
- `snapshot-manifest.json` — признак успешного полного снимка и контрольные суммы всех архивов.

Скрипт завершается ошибкой, если не удалось создать или проверить хотя бы одну часть. По умолчанию хранит 14 последних снимков и удаляет только старые **папки снимков внутри** `backups\snapshots`. Не чистить старые снимки:

```powershell
npm.cmd run backup:all -- -DisableCleanup
```

Проверить уже созданную копию:

```powershell
npm.cmd run verify:backup -- backups\snapshots\2026-08-10_22-00-00
```

## Планировщик Windows

1. Откройте «Планировщик заданий» → «Создать задачу».
2. Вкладка **Триггеры**: ежедневно, например в 20:00.
3. Вкладка **Действия**: программа `powershell.exe`.
4. Аргументы:

```text
-NoProfile -ExecutionPolicy Bypass -File "C:\ПУТЬ\К\ПРОЕКТУ\scripts\backup-all.ps1"
```

5. В «Начать в» укажите папку проекта. Раз в неделю проверяйте историю задачи и копируйте свежий снимок на внешний диск.

## Восстановление БД

Восстановление заменяет содержимое текущей БД. Сначала создайте свежий снимок и сделайте пробный запуск без изменений:

```powershell
npm.cmd run restore:database -- backups\snapshots\<дата>\izlk-database_*.json.gz --dry-run
```

Для реального восстановления остановите приложение, убедитесь, что выбран нужный архив, затем выполните:

```powershell
npm.cmd run restore:database -- backups\snapshots\<дата>\izlk-database_*.json.gz --confirm=RESTORE
```

После этого запустите приложение и проверьте вход, договор, документы и площадку. Восстановление файлов намеренно не автоматизировано: сначала распакуйте ZIP в отдельную временную папку, сравните состав, и только затем заменяйте рабочее хранилище. Это предотвращает случайное удаление оригиналов.

## Важные правила

- Один архив на этом же диске не является надёжной резервной копией.
- Храните как минимум одну копию вне сервера/ПК.
- Раз в месяц выполняйте `--dry-run` и тестовое восстановление на отдельной тестовой БД.
- Старые архивы прежнего формата `izlk-logical-backup-v1` остаются поддержанными для восстановления, но не имеют manifest-проверки.
