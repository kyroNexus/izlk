# Запуск ИЗЛК для работы компании

## Перед первым рабочим днём

1. В разделе **Настройки** создайте отдельную учётную запись каждому сотруднику.
2. Смените демонстрационные пароли `admin123` и `manager123`. Общие пароли между сотрудниками не используйте.
3. Проверьте права на одном тестовом договоре:
   - администратор видит всё и управляет сотрудниками;
   - менеджер видит свои договоры и связанные с ними данные;
   - наблюдатель видит только назначенную ему работу, не меняет данные и не видит суммы договоров.
4. В `.env` укажите постоянные `STORAGE_PATH` и `INBOX_PATH`. Эти папки должны находиться на диске, который резервируется.
5. Создайте резервную копию файлов и базы командами из раздела ниже.
6. На одном тестовом договоре пройдите всю цепочку: договор → проект → площадка → монтажный отчёт → задача → исполнительная документация.

Для запуска на текущем компьютере дважды щёлкните **ЗАПУСТИТЬ ИЗЛК.cmd** в папке проекта. Не закрывайте открывшееся окно, пока сотрудники работают в системе.

## Ежедневная работа

- Новый договор создаётся вручную или через **Договоры → Загрузить договор**.
- Файлы из общей папки проверяются в разделе **Очередь импорта**.
- Перед созданием карточки сотрудник проверяет распознанные поля. Полный автомат без подтверждения пока намеренно выключен.
- Задачи ведутся с исполнителем, сроком, приоритетом, статусом и комментариями.
- При остановке площадки обязательно указывается причина.
- Фото, затраты на технику и материалы заносятся в монтажный отчёт КЖ или КМ.
- Файлы исполнительной документации загружаются непосредственно в нужный раздел карточки договора.

## Резервные копии

Файлы приложения:

```powershell
npm.cmd run backup:files
```

База данных PostgreSQL/Neon:

```powershell
npm.cmd run backup:database
```

Архивы сохраняются в папку `backups`. Как минимум одну актуальную копию храните на другом физическом диске или в защищённом облаке. Раз в месяц проверяйте восстановление тестовой копии — наличие файла само по себе ещё не гарантирует возможность восстановления.

## Обновление приложения

1. Создать резервные копии файлов и базы.
2. Остановить рабочий сервер.
3. Выполнить миграции: `npx.cmd prisma migrate deploy`.
4. Собрать приложение: `npm.cmd run build`.
5. Запустить: `npm.cmd run start`.
6. Проверить вход, договоры, документы, задачи и площадки.

## Что остаётся вне текущего рабочего контура

- бухгалтерия и просрочки оплаты из 1С;
- автоматический обмен с базой 1С до согласования формата и доступа;
- OCR фотографий и отсканированных PDF без текстового слоя;
- управленческие отчёты, состав которых ещё не утверждён руководителем.

Эти ограничения не мешают начать вести договоры, контрагентов, проекты, задачи, площадки, монтажные отчёты, документы и исполнительную документацию в одном месте.
